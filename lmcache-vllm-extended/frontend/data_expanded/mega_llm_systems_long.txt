A Comprehensive Review of Large Language Model Serving, Inference Optimization, and Memory Management Mechanisms

Abstract
The deployment of Large Language Models (LLMs) such as GPT-3, LLaMA, and Qwen has revolutionized artificial intelligence, enabling unprecedented capabilities in natural language understanding, reasoning, and generation. However, serving these models in production environments presents formidable challenges due to their massive computational and memory requirements. This comprehensive review examines the bottlenecks associated with LLM inference, focusing primarily on memory management, KV cache optimization, dynamic scheduling, and distributed serving architectures.

1. The Inference Bottleneck: Autoregressive Generation and the KV Cache
Unlike model training, which processes entire sequences in parallel, LLM inference for generative tasks is inherently sequential. Autoregressive decoding generates one token at a time, where each step requires the attention mechanism to attend to all previously generated tokens. 

To avoid recomputing the key (K) and value (V) vectors for past tokens at every generation step, inference engines employ a KV cache. While this significantly reduces computational redundancy, it shifts the bottleneck from compute to memory bandwidth and capacity. As the sequence length and batch size increase, the KV cache grows dynamically, eventually consuming the majority of available GPU memory.

2. Memory Fragmentation and PagedAttention
Traditional deep learning frameworks allocate memory in contiguous blocks. Because the length of an LLM's generated response is unknown apriori, systems often over-allocate memory to accommodate the maximum possible sequence length. This static allocation leads to severe internal and external memory fragmentation, wasting up to 60% of GPU memory.

To address this, PagedAttention (introduced by vLLM) applies operating system virtual memory concepts to the KV cache. By breaking the cache into fixed-size blocks (e.g., 16 or 32 tokens per block) and mapping logical blocks to non-contiguous physical blocks via a block table, PagedAttention eliminates internal fragmentation and enables efficient memory sharing across requests (e.g., in beam search or parallel decoding).

3. Dynamic Scheduling and Iteration-Level Batching
Standard request-level batching assumes all requests in a batch finish simultaneously, which is highly inefficient for LLMs where output lengths vary wildly. Modern inference engines employ continuous batching (or iteration-level scheduling). As soon as a request in the batch emits its End-Of-Sequence (EOS) token, it is removed, and a new request from the queue is immediately injected into the batch.

However, injecting a new request introduces a "prefill" phase. The prefill phase requires processing the entire input prompt in a single forward pass, which is highly compute-intensive. If scheduled alongside the memory-bound "decode" phases of other requests, it can cause severe latency spikes (generation stalls) for the decoding requests.

4. Mitigating the Prefill-Decode Interference
Systems like Sarathi-Serve address the prefill-decode interference by introducing chunked prefills. Instead of processing a massive 4,000-token prompt in one go, the system chunks the prompt into smaller segments (e.g., 512 tokens). These chunks are then batched with decoding requests. By carefully managing the arithmetic intensity of the batch, the system avoids starving the decoding requests, ensuring smooth, stall-free generation and low Time-Between-Tokens (TBT).

5. KV Cache Offloading and Distributed Storage
Even with PagedAttention, GPU memory is ultimately finite. For applications requiring massive contexts (e.g., Retrieval-Augmented Generation or processing entire books), the local GPU cache is insufficient. Systems like LMCache and InfiniGen explore offloading the KV cache to CPU RAM, NVMe SSDs, or dedicated cache servers. 

These systems must intelligently prefetch and swap KV cache blocks to hide the PCIe or network transfer latency. Strategies include semantic prefetching, where the system predicts which tokens will have high attention scores and only loads those specific KV blocks back into GPU memory, thus avoiding full-context transfers.

6. Conclusion
The landscape of LLM inference is rapidly evolving, driven by the tension between hardware limitations and model size. Innovations in memory paging, iteration-level scheduling, chunked prefilling, and distributed caching are critical to making LLM deployment economically viable and interactive for end users. Future directions will likely involve deeper hardware-software co-design and sparsity-aware attention mechanisms to further tame the KV cache bottleneck.
